# 从中文意图寻找原句，以及从草稿出发的 AI 写作（本 fork）

这是 Yu-Qiao-sjtu/WispPaper 在上游“用户写稿、系统推荐参考句”基础上的扩展，不代表上游已经接受这一产品方向。首版针对一个章节完成“提供草稿 → AI 生成 → 预览 → 采用 → 必要时恢复”，不自动生成未经验证的整篇论文。

## 中文写作意图 → 英文语料 → 原文与译文

1. 中间写下想表达的中文，选择摘要/导言/方法/结果/讨论。点「寻找语料」或右侧「寻找」执行；右侧查找框非空时优先用它，否则使用中间光标所在的完整段落。光标在空行时使用前一个非空段落。输入或移动光标不自动调用模型。
2. 中文或混合输入由设置中的翻译模型识别，返回等价英文检索表达与关键词，均显示供核对；保留否定、比较与不确定性，不把生成的英文当成论文原文。纯英文直接查找；空输入显示本章节各篇开头，不调用意图模型。
3. 用这些英文词匹配本库已保存的同章节句子。当前是词项排序，不是向量语义检索；排名靠前不代表原文支持用户论断。进入/切换章节默认展示开头；文字或光标位置变化时标明上次结果需要更新。当前句段最多 12000 字节，过长时提示缩短，不静默截去前面的限定条件。
4. 点击候选句正文或「原文与翻译」。有 PDF 页码时在详情区打开 PDF、跳页并定位；只有摘要时打开文献记录，不编造页码。中间草稿不被替换，候选卡片显示对应英文原句及中文译文，可分别复制。
5. 单句翻译仅发送该句和标题作为术语背景，使用翻译模型；译文按标题、句子与翻译规则缓存到当前库，重复点击不重复请求。失败提供重试。机器译文不是新证据，仍以论文原文上下文为准。

改稿、改变查找内容或切换章节后，旧检索请求返回的结果被忽略。切换候选句时，译文按内容缓存键各自保存，不让先前句子的迟到译文覆盖当前句子。中文意图没有可用模型时明确报错，仍可输入英文检索。检索不会改写草稿；AI 写作不会使用已标为过期的候选结果。

## 使用

1. 在「设置 › AI」配置提问模型；当前沿用它的接口、代理和思考设置，不需要另配写作服务。
2. 打开「写作」，选择摘要、导言、方法、结果或讨论，粘贴粗稿、提纲或尚未润色的内容。可以中文输入。
3. 可选填写「写作要求」，例如“保持中文、保留数据与限定条件、引文紧邻对应论断”。要求随这个文献库保存，各章节共用。
4. 点击「AI 帮我写」。会发送当前章节草稿、写作要求和当时右侧候选结果中至多 12 条参考句。不是读取整库全文；没有合适候选时仅依据草稿整理。
5. 建议出现在原稿下方，带模型、核对提示与所提供来源入口。检查后点「采用建议」，无需从聊天复制。原稿先保留，随时可复制；采用后若正文未再修改，可点「恢复生成前原稿」。

草稿、写作要求及每章节最近一份建议/原稿保存在当前文献库；未采用的建议重启后仍可看到。切换章节恢复各自的建议。重新生成会替换该章节之前的建议记录，当前版本不是完整稿件历史库。

## 后续写作 Skill

本版把基础事实约束和可选表达要求分开：`writing::SYSTEM` 提供保留事实、不编造结果/引用的提示；`WritingInput.rules` 承载用户后来提供的格式/语言规则。后续可单独增加读取 Skill 正文、版本与资源的适配器，并在原有请求流程里传入规则。

目前“写作要求”是纯文本，不会自动发现、安装或执行 SKILL.md 包、脚本、MCP 或其他运行时。不能因为粘贴了一段规则，就宣称已经完成 Skill 格式兼容或规范校验。这里也没有 AI 文本检测通过率承诺。

## 审阅、来源与限制

- 生成不自动改稿；生成期间继续编辑后，旧建议不能直接覆盖新稿。采用时同时核对编辑器、数据库正文及已展示的建议快照，冲突需重新审阅或重新生成。
- 失败、格式无效、空答复和未知来源标记不覆盖原稿；停止等待、切换章节或关闭文献库后，迟到结果被忽略。已经发送的远端请求可能仍在处理，不能承诺取消计费。
- 模型使用所提供的 `[[S1]]` 等标记引用候选，程序将其换成实际作者年份；未知标记被拒绝。来源文件/页码及原句随建议保存，入口供用户核对。这不证明模型没有用别的写法虚构引用，也不证明引文支持全部论断。
- 参考句是片段，不是完整研究上下文；尤其不能把他人方法与结果写成自己的实验。数字序列变化会提示，但这只是辅助，不能保证单位、公式、数值或科学含义完全一致。
- 若采用后又修改正文，直接恢复会被阻止，防止覆盖新的手改；仍可复制保留的原稿。当前仅检查文本快照，不是逐字修订或任意版本合并。
- 默认保持草稿语言，也可明确要求翻译；最多 60000 字节草稿、12000 字节写作要求和 12 条/12000 字节候选原句。超过限制要分段处理，不静默截断原稿。
- 当前处理的是原有纯文本章节编辑器，不包含 DOCX/公式保真、自动全文写作、外部检索、导出或完整参考文献排版。

## 验证与手工检查

离线检查：`cargo test --workspace`；`cargo clippy --all-targets -- -D warnings`。新增 core 测试覆盖输入、来源标记、数字提示、过期建议与恢复；Store 测试覆盖重启持久化、旧库补表、正文/建议并发冲突和事务写回；net 使用回环假服务验证真实请求到建议再到采用，不使用真实模型或 API Key。

手工用独立的 `WISP_PAPER_HOME` 与 `cargo run -p wisp_core --example mock_model -- 8787`，配置 Anthropic、`http://127.0.0.1:8787`、任意测试 key/model。确认粗稿生成后仍在、采用后改变、恢复后还原；修改草稿再采用应被阻止；切换章节、停止等待和退出重开后检查状态。测试数据与真实文献库分开。

Debug 开发步骤新增 `write-ai`、`write-apply`、`write-restore`、`write-cancel`、`write-rules:<文本>`，与已有 `write:<section>`、`draft:<文本>` 一起用于上述流程。它们不在 release 构建启用。

意图检索另有 `write-find`、`write-query:<文本>`、`write-candidate:<从0开始的候选序号>`。离线假模型会分别打印 `writing-intent`、`writing-sentence`，可验证点击前没有请求、点击寻找后有意图请求、点击原句后有单句翻译请求，以及再次点击使用缓存。
